BROWSER STORAGE

ブラウザに保存されるデータ

ゲスト・未認証、またはM3の移行が完了していない状態では、入力条件、調整対象ボックス、仮想敵ボックス、作業中の下書き、候補形式の設定をブラウザのlocalStorageへ保存します。これはブラウザごとの保存であり、運営者のサーバーへ自動送信されません。

M3完了後の認証済みsessionでも、同期のためにUID別のlocal repository、未送信outbox、cloud draft、migration markerを同じブラウザへ保持します。計算結果、候補一覧、Worker state、チュートリアルの入力・保存・同期は対象外です。

主な保存キーは次のとおりです。UIDやdeviceIdの部分は値に応じて変わります。

  • ゲスト・legacy: championcreator.box.v1、championcreator.enemy-box.v1、championcreator.box.default-example.v1
  • UID別: championcreator.sync.v1.<uid>、championcreator.cloud-draft.v1.<uid>.<device>、championcreator.draft.v1.<uid>.<device>、migration marker（championcreator.migration.v1.<uid>）

ブラウザデータを削除すると、サインイン状態とは別にブラウザ内データが消えることがあります。JSONバックアップを書き出し、ブラウザのプロファイルや利用するスマホ・PCを変更する前に保管してください。

FIREBASE

Firebaseで扱うデータ

Googleの「scope」は、アプリがどの情報や機能を使えるかを示すアクセス権の種類です。Googleでログインすると、Firebase Authenticationがアカウント識別子（UID）、表示名、メールアドレス、プロフィール画像、session状態を扱います。ChampionCreatorはGoogleのcredentialやaccess tokenをアプリの保存データやexportへ含めません。Google Driveのファイル、連絡先、Gmailのメール本文を見る追加権限は要求しません。

M3完了後の同期では、FirestoreのアカウントUID配下に調整対象・仮想敵ボックスの保存slot（syncRecords）と、ブラウザ別の作業中cloud draft（drafts）を保存します。保存されるのは入力条件と同期メタデータで、計算結果、候補一覧、Worker state、チュートリアルstateではありません。

通常のbox・draft削除は、競合確認と復元のためpayloadを保持したtombstoneとして同期します。アカウント削除を選んだ場合だけ、対象UIDの両collectionを物理削除して空になったことを確認し、最後にFirebase Authenticationのアカウントを削除します。

Firebase Web configはWebアプリ用の公開設定だけを使います。Firebase Admin credential、service account key、Google OAuth client secretなどの秘密情報はbrowser bundle、repository、Pages artifactへ含めません。

THIRD-PARTY REQUESTS

Google Analyticsとフォント

アプリ、ガイド、このページではGoogle Analytics 4（測定ID G-VCGTV67QC2）を読み込み、ページ表示などの標準的な利用状況を計測します。ChampionCreatorは、調整条件、ボックス内容、cloud draft、UID、credential、tokenをAnalyticsイベントへ意図的に送信しません。Google側のCookie、ログ、保持期間、地域処理はGoogleのプライバシーポリシーに従います。ブラウザの設定や拡張機能で外部計測を制限できます。

画面の日本語フォントにはGoogle Fontsの LINE Seed JP を使います。フォントを読み込むと、ブラウザからGoogle Fontsへ通常のHTTPリクエストが送られます。フォント提供元へChampionCreatorの入力条件やアカウントデータを送る処理はありません。

Firebase SDKとApp Checkを有効にした公開環境では、FirebaseのAuth・Firestore・App Check用リクエストも発生します。Firebaseのサービス提供・ログ・保持はFirebaseのプライバシー情報に従います。

EXPORT

アカウントデータの書き出し

ヘッダーのアカウント管理から書き出しを開始すると、まず手動同期を行い、Firestoreの syncRecords と drafts をserver readします。読み取りエラー、未送信outbox、競合、破損・未対応payloadが残っているときは、完全な書き出しと表示せず、警告付きの部分書き出しまたは中止になります。

JSONには schemaVersion、exportedAt、UID、サニタイズしたプロフィール、調整対象・仮想敵ボックス・cloud draftを含めます。credential、access token、秘密鍵、ゲストnamespaceは含めません。ダウンロード用Blob URLは処理後に破棄します。

このブラウザだけにあるguest / legacyデータはcloud exportの対象ではありません。必要な場合は各ボックスのバックアップ機能を使って別に退避してください。

DELETE & RETRY

アカウント削除と失敗時の再試行

アカウント削除を始めると、Google popupで最近のログインを再認証し、popup後にUIDが変わっていないことを確認します。その後、同じタブの同期・保存queueを停止して進行中の処理を待ってから、対象UIDのFirestore recordsを列挙し、450件以下のbatchで削除し、空になったことを再確認します。続いてUID専用localStorageを削除し、Firebase Authenticationのdeleteを最後に呼びます。

再認証、popup、Firestoreの列挙・batch削除、空確認、UID専用local cleanupのどこかで失敗した場合はAuthenticationを削除せず、失敗理由を表示して再試行できます。最後のAuthentication削除だけが失敗した場合も、sessionは維持され、クラウド・UID専用localの削除済み状態から再試行できます。成功後はAuth listenerの状態変更でゲストnamespaceへ切り替わり、重複したsign outは行いません。

アカウント削除で消すのはUID専用の保存だけです。legacyの championcreator.box.v1 / championcreator.enemy-box.v1、既定サンプルmarker、guestデータは残ります。これはログイン前からこのブラウザだけにあるデータを、別アカウントの削除で巻き込まないためです。ブラウザだけのデータを消す場合は、ブラウザのサイトデータ削除や通常のbox操作を使ってください。

RETENTION & SECURITY

保持期間と安全性

  • cloud draftはアカウントあたり最大10件、保持期間は30日です。期限切れのdraftは起動、focus、online復帰、手動cleanupで削除します。
  • ボックスと同期メタデータは、ユーザーが削除するまでUID境界のFirestoreとブラウザへ保持します。通常の削除ではtombstoneを使い、アカウント削除で物理削除します。
  • 静的PagesからFirebase client SDKを呼ぶ構成で、ChampionCreator独自のAdminサーバーやGoogle Drive保存はありません。
  • 共有ボックス、リアルタイム共同編集、Google以外のログインproviderは提供していません。

2026年8月21日の公開検証では、custom domain、Security Rules、Googleログイン、Firestore read / write、再読み込み、別ブラウザへのbox・cloud draft反映と削除同期を確認しました。App CheckはCloud FirestoreとAuthenticationで検証済みリクエスト100%・未検証0%を確認したうえで適用しています。
