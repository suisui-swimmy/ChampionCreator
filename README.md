# ChampionCreator

ChampionCreator は、Pokemon Champions / Pokemon Showdown 系のダメージ計算に準拠しながら、複数の仮想敵条件を同時に満たす能力ポイント配分を探索する静的 Web アプリです。
耐久調整、火力ライン、素早さラインを同じ作業画面で扱い、条件を満たす候補の SP 配分、使用SP、残りSP、最厳条件、ダメージ詳細を比較できます。

公開URL: <https://championcreator.suisui-swimmy.com/>

使い方ガイド: <https://championcreator.suisui-swimmy.com/guide/>

プライバシーとデータの取り扱い: <https://championcreator.suisui-swimmy.com/privacy/>

画面の操作手順は使い方ガイド、計算・保存・同期の詳細仕様と対応範囲はこのREADMEを参照してください。

## 実装機能

- 複数の仮想敵シナリオを同時に満たす `H / B / D` 耐久配分を探索する
- 1つのシナリオ内で複数攻撃を順番に受ける条件を評価する
- 必要耐久回数と必要生存率を満たす候補だけを返す
- 調整対象が仮想敵を倒すための `A / C` 火力ラインを探索する
- 任意の相手や実数値を抜くための `S` ラインを探索し、共通・相手・調整対象それぞれの素早さ条件を指定できる
- 直接攻撃に加えて、明示した状態異常、設置物、継続ダメージ、持ち物回復を順番どおりに評価する
- 調整対象と各攻撃カードの `レベル` は50でロックし、ロックを外したときだけ任意の1〜100へ変更する
- 各攻撃カードの `威力` 欄で、計算に使う実効基礎威力を確認し、対応技は条件ステッパーまたは任意値で指定する
- `A / C / S` の必要SPを固定条件として、耐久候補の SP 予算へ統合する
- 候補ごとの最厳条件を表示し、どの条件がボトルネックかを確認できるようにする
- 技・特性・持ち物の入力候補を、[Pokemon Champions Battle Data](https://championsbattledata.com/) の `Current` 使用率順で表示する
- 調整対象と攻撃カードの5×5性格表へ、同データの上位10件にある実使用率を濃淡で表示し、詳細な％・順位を各セルのARIAラベルへ含める
- ヘッダーのシングル／ダブル切替で、入力サジェストの基準と現在の全攻撃カードのルールをまとめて切り替えられる（初期値はシングル）

## 技術仕様

### Runtime / build

- Frontend: React 19 + TypeScript + Vite
- Test runner: Vitest
- Hosting: GitHub Pages を想定した静的配信
- ブラウザ内保存 / アカウント同期: 未ログイン時と初回統合を保留している間は、ブラウザ内保存を優先して利用できます。Googleログイン後に初回統合を完了すると、調整対象・仮想敵ボックスとブラウザ別クラウド下書きを、アカウントの識別子（UID）単位で同期します。クラウド同期に失敗しても、ブラウザ内保存とJSONバックアップは利用できます
- PWA: Web App Manifest に対応。Service Worker によるオフラインキャッシュは未実装

### Damage calculation boundary

- ダメージ計算エンジンは `@smogon/calc` に依存します
- 現在の直接依存は、`@smogon/calc@0.11.0` を upstream master `49d4d86` から作成した vendor tarball です
- 計算世代は `Generations.get(9)` を使用します
- `src/calc/smogonAdapter.ts` が `Pokemon` / `Move` / `Field` / `Side` への変換境界です
- 定数ダメージは `@smogon/calc` の直接ダメージへ混ぜず、Champions HPルールと順序付きHPイベント評価層で処理します
- 現在対応する選択式HPイベントは `いのちのたま反動`、`すなあらし`、`どく`、`もうどく`、`やけど`、`ステルスロック`、`まきびし`、Champions版 `しおづけ`、`オボンのみ`、`たべのこし`、`ゴツゴツメット`、`さめはだ／てつのトゲ` です
- `ステルスロック` / `まきびし` → 直接攻撃 → 明示したヒットごとの接触反動・`オボンのみ` → 明示した`いのちのたま` → ターン終了時の天候 → 状態異常 → `しおづけ` → `たべのこし` の順でHPを更新します
- `もうどく` は開始段階を1〜15、`まきびし` は層数を1〜3で指定できます。`オボンのみ` は連続技の各ヒット後にも判定し、同じシナリオ内では1回だけ発動します
- HPイベントの対象は効果から自動決定し、`いのちのたま反動`・接触反動は技使用者、それ以外の選択式効果は技の被弾側へ適用します
- 現在HP依存ダメージ・威力は選択した技から自動判定し、各攻撃時点のHPで直接ダメージを再計算します
- `威力` 欄と計算結果には、タイプ一致・相性・持ち物・特性などを掛ける前に、今回の `@smogon/calc` 計算で使った実効基礎威力を表示します。現在HP依存技は閉じたロック中に自動再計算し、ロックを外すと任意威力を直接入力できます。素早さ・体重・状態などから決まる技、連続技、固定ダメージ技、変化技も区別します
- アプリだけでは推測できない戦闘中条件を持つ `ゆきなだれ`、`きまぐレーザー`、`おはかまいり`、`ふんどのこぶし`、`りんしょう`、`はきだす`、`じだんだ`、`やけっぱち` は、合法な威力候補を `▲ / ▼` で切り替えられます。詳細ポップオーバーでは条件名の確認と任意威力の指定もできます
- `ふくろだたき` は威力欄から参加ポケモンと攻撃順を指定し、各ポケモンの攻撃種族値から1ヒットごとの威力を自動計算します。各枠のロックを外すと個別の任意威力も指定でき、参加上限は使用者を含めてシングル3体・ダブル4体です
- 通常の耐久・火力ラインでは、技固有の使用者側反動、HPコスト、使用者ひんしを自動適用しません。これらを理由に指定した攻撃回数を途中で打ち切る、双方の行動を追う完全な対戦シーケンスは今後の対象です
- タイプ相性・地面にいるかの判定には `@smogon/calc` の世代データと判定を使い、`マジックガード`、`ポイズンヒール`、`たいねつ`、`あつぞこブーツ` など主要な無効化・変換も反映します
- アプリ側では独自のダメージ計算式、独自のタイプ相性、独自の乱数分布を主計算として実装しません
- 最終候補の合否判定は、resolver 済み canonical name を `@smogon/calc` に渡して再評価します
- 公式画像、タイプ色、日本語表示名は UI 表示用であり、計算結果には影響しません

### Dynamax / Gigantamax note

- 通常ダイマックスは、ポケモンの別 species ではなく、計算条件のフラグとして扱います
- 2026-06-20 時点で取り込んだ upstream `@smogon/calc` では `-Gmax` species が候補データから外れているため、ChampionCreator でもキョダイマックスフォームを canonical species としては受け付けません
- Pokemon Champions 側で今後キョダイマックス相当のゲーム内実装が追加される可能性はあるため、将来対応する場合は通常ダイマックスとは別の mechanics として設計し、`@smogon/calc` 側の対応または明示された仕様に追従します
- `@smogon/calc` に存在しない `-Gmax` species や専用効果を、アプリ側の独自ダメージ補正として先行実装しません

### Japanese localization layer

ChampionCreator は、日本語入力・表示と Showdown canonical name を分離します。

- 日本語名、別名、検索用文字列は `src/localization/` で解決します
- resolver の入力種別は Pokemon / Move / Item / Ability / Nature / Type を分けて扱います
- resolver は `exact` / `alias` / `ambiguous` / `not-found` を返し、曖昧さや欠損を握りつぶしません
- 計算 adapter には日本語入力を直接渡さず、Showdown canonical name だけを渡します
- 生成済みデータは `src/data/generated/*.gen.json`、手動補正は `src/data/overrides/` に置きます

日本語レイヤーの設計は `@suisui-swimmy/damage-calc-ja-layer` の方針をベースにしています。`@suisui-swimmy/damage-calc-ja-layer` は開発時の参考実装であり、ChampionCreator 本体はそこへ runtime import しません。必要な resolver、データ、adapter 方針だけを本体側へ移しています。

### Search model

- `H / B / D` は1つの候補として同時探索します
- `A / C / S` は入力済みSP、火力ライン、素早さラインを固定条件として扱います
- 探索対象は Pokemon Champions の Stat Points / SP です
- 探索は Web Worker で実行し、UI 側は requestId で古い結果を破棄します
- 候補は使用SP、残りSP、最厳条件への余裕などで順位付けします
- 候補一覧は、`総合耐久指数=HBD/(B+D)`、`物理耐久指数=H*B`、`特殊耐久指数=H*D` でも並び替えられます。H/B/D は候補適用後の実数値（H=`maxHP()`、B=`stats.def`、D=`stats.spd`）を使い、SP値の積ではありません
- 3つの耐久指数はシナリオ固有のダメージ、タイプ相性、特性、持ち物、HPイベントを含まない並び替え用の補助指標で、検索の合否判定やシナリオ評価を置き換えません
- 上位候補は最終的に全シナリオで再評価します

### 素早さラインの条件

素早さ調整では、調整対象の最終Sと相手の最終Sを比較します。条件は、全体へ適用する `共通S条件`、相手側へ適用する `相手S条件`、調整対象側へ適用する `調整対象S条件` に分かれています。

- `共通S条件` は、ルール、天候、フィールド、行動順（通常／トリックルーム）を指定します。トリックルームと、おいかぜ（両側）は同時に指定できます
- `相手S条件` と `調整対象S条件` は、それぞれの状態異常、道具倍率、特性倍率、おいかぜを個別に指定します。まひは通常Sが1/2になり、状態異常時の`はやあし`はSが1.5倍になります
- `任意S値` は相手の最終Sを直接入力する条件です。この場合、相手ポケモンのS能力や相手S条件は使わず、調整対象側と共通S条件だけを反映します
- 道具倍率・特性倍率は通常`自動`で、手動倍率を選ぶと倍率欄が金色になり、欄内へ`手動`を表示します。選択中の持ち物・特性に実際の自動S補正がある場合は、その元入力を暗色＋金枠で示します。手動倍率は自動補正をそのカテゴリだけ置き換える最終Sへの数値上書きで、特性の発動条件や丸め順まで完全に再現するものではありません。`かるわざ`・`スロースタート`の発動状態や、`こだいかっせい`・`クォークチャージ`でSが上昇する状態を直接指定する専用UIも未対応です

## SP モデル

Pokemon Champions の Stat Points / SP を探索単位にしています。

- 各能力は `0..32 SP`
- 6能力合計は `66 SP` まで
- `0 SP` は `0 EV` として扱います
- `1 SP` 以上は `4 + (SP - 1) * 8 EV` へ変換します
- `32 SP` は `252 EV` です
- `@smogon/calc` へ渡す直前に、実数値が一致する Showdown EV 相当へ変換します
- SP配分バーは、性格上昇補正で無補正時より実数値が多く伸びる位置を赤、性格下降補正で伸びが少なくなる位置を青で示し、選択中のレベルにも追従します。未到達位置は控えめに、到達済み位置は枠と発光で強調します

## 使い方

1. 公開URLを開く
2. 調整対象のポケモン、性格、特性、持ち物、現在SPなどを入力する
3. 仮想敵シナリオに相手、技、攻撃側条件、必要耐久回数、生存率などを入力する
4. 調整対象と各攻撃カードの `レベル` は通常50でロックされ、変更するときだけロックを外す。技の横の `威力` 欄で計算値を確認する。`▲ / ▼` がある技は戦闘中条件に合う威力へ切り替え、欄を押すと条件名や任意入力を確認できる。HP依存技は閉じたロック中に現在HPから自動計算され、ロックを外すと任意値を入力できる。`ふくろだたき` は威力欄を押して参加ポケモンと攻撃順を指定する。レベルと威力のコンパクト欄はTabキーの移動対象外だが、クリック・タッチでは操作できる
5. 必要ならシナリオを `耐久調整` / `火力調整` / `素早さ調整` に切り替える
6. 定数ダメージや回復を含める場合は攻撃カードの `定数ダメージ・回復` を開き、効果を追加する。対象・発動タイミング・頻度は効果ごとに自動決定される。HP依存技は設定一覧とは別の補足を表示し、各攻撃・各ヒット時点の現在HPから自動計算する
7. `計算開始` を押す
8. 候補一覧から配分、残りSP、最厳条件、適用威力、直接ダメージと定数ダメージ・回復の内訳を確認する
9. 使いたい候補の `適用` で調整対象へ反映する

### 入力サジェストと性格の使用率

技・特性・持ち物の入力候補は、Pokemon Champions Battle Data が提供する `Current` の使用率データをもとに並び替えます。ヘッダーの「シングル」「ダブル」を切り替えると、サジェスト基準に加えて、現在の全シナリオ・全攻撃カードの `状況条件 > ルール` を同じ形式へ一括変更します。各攻撃カードのルールはその後も個別変更でき、個別変更からヘッダーへは逆同期しません。次にヘッダーを切り替えた場合は、個別変更を含む現在の全攻撃カードへ再度一括適用します。

選択したサジェスト基準だけが同じブラウザに保存されます。条件JSONやボックスから読み込んだルールは、読み込み時にはヘッダーの形式で上書きせず、次にヘッダーを操作した時だけ一括変更します。ダブル4体の `ふくろだたき` をシングルへ一括変更した場合は、既存のルール変更と同じく参加上限3体へ整理されます。

技・特性・持ち物は、使用率データに掲載された候補を先頭へ移し、未掲載候補は従来の五十音順で残します。順位や使用率そのものは表示せず、候補の並び順だけに反映します。

性格は、調整対象と各攻撃カードの5×5能力補正表へ実使用率の濃淡を表示します。画面上には詳細な％・順位を追加表示せず、各セルのARIAラベルへ性格、能力補正、選択中のシングル／ダブル使用率、順位を含めます。提供データは上位10件のため、掲載されていない性格は `0%` と扱わず、ARIAラベルでは `上位外／データなし` と区別します。使い方ガイドのチュートリアル画面では、技・特性・持ち物の候補順にダブル使用率データを使い、性格表は使用率表示なしを維持します。

データは1日1回確認し、更新されている場合だけ反映します。提供元とデータ更新日はアプリのフッターに表示します。

画面上での入力手順、候補の見方、保存・同期の始め方は[使い方ガイド](https://championcreator.suisui-swimmy.com/guide/)を参照してください。

## ブラウザ内保存

入力中の調整対象とシナリオは、変更が止まってから約0.75秒後に、ボックスとは別の「作業中の下書き」として同じブラウザへ自動保存されます。次回起動時に下書きが見つかっても自動では適用せず、`下書きを復元` / `下書きを破棄` を選べます。

下書きに保存するのは入力条件だけです。計算結果、候補一覧、Workerの進行状態は保存しません。ガイド内のチュートリアルも保存対象外です。ブラウザの保存容量不足などで保存できない場合は、画面にエラーと再試行操作を表示します。

調整対象ボックスには、調整対象、シナリオ、火力ライン、素早さラインなどの入力条件をまとめて保存できます。仮想敵ボックスには、調整対象を変えずに、よく使う仮想敵シナリオだけを保存できます。

調整対象ボックスへ現在の条件を保存または上書きすると、その内容を確定保存として扱います。作業中の下書きは削除し、次に入力を変更するまで`ボックスに保存済み`と表示します。ボックスから保存を読み込むと、その入力条件を次の下書きとして自動保存します。空スロットを読み込んだ場合は、作業中の下書きも破棄します。

### 初回統合

Googleログイン後、ブラウザ内の既存ボックスとクラウド側の保存を初めて結び付けるときは、保存データの扱いを選びます。選択肢は`統合` / `クラウドを使用` / `このブラウザを使用` / `あとで決める`です。

- `統合`: 同じID・同じ内容は1件にまとめ、同じIDで内容が異なる保存は競合コピーとして両方を残します
- `クラウドを使用`: クラウド側の保存をアカウントの保存内容として使います
- `このブラウザを使用`: このブラウザの保存をアカウントの保存内容として使います
- `あとで決める`: 統合を保留し、ブラウザ内保存を維持します

統合が成功するまでは、既存の`championcreator.box.v1`、`championcreator.enemy-box.v1`、既定サンプルの削除状態を残します。失敗しても既存データやJSONバックアップを失いません。未変更の既定サンプルは重複させず、ユーザーが削除したサンプルを勝手に復活させません。

初回統合の対象は、調整対象ボックスと仮想敵ボックスに保存した入力条件です。計算結果、候補一覧、Workerの状態、チュートリアル、作業中のクラウド下書きは含めません。

### ボックス同期

Googleログイン後に初回統合を完了すると、調整対象ボックスと仮想敵ボックスをアカウントの識別子（UID）ごとに同期します。作成、上書き、名前変更、複製、削除、読み込み、バックアップの書き出し・読み込みが対象です。

保存操作は、まずこのブラウザへ確定します。その後、未送信操作を順番に保持するキュー（`outbox`）へ追加し、クラウドデータベース（Firestore）へ送ります。同期は起動時、画面へ戻ったとき、オンライン復帰時、ボックス操作後、`今すぐ同期`を選んだときに行います。ネットワーク、権限、利用上限などの理由でクラウド同期に失敗しても、ブラウザ内の保存とJSONバックアップは利用できます。

通常の削除では、元の保存内容を残したまま削除済みと記録します（`tombstone`）。同じ保存を複数のブラウザで変更した場合や、更新と削除が重なった場合は、一方を自動採用せず`競合あり`として両方を保持します。クラウド上の1件が破損していても、その保存だけを問題として分離し、正常な一覧を空にしません。

認証済みのアカウントでバックアップを読み込むと、追加・更新・削除・変更なし、競合コピー、重複除外の件数を確認してから、`統合`または`クラウド全体を置き換え`を選べます。読み込めない保存が含まれる場合は、既存データを失う可能性がある置き換えを無効にします。ゲストまたは未ログインの場合は、`統合`または`このブラウザの保存を置き換え`を選べます。

### ブラウザ別クラウド下書き

Googleログイン後に初回統合を完了すると、作業中の下書きもブラウザごとにクラウドへ保存できます。ブラウザ内には入力変更後約0.75秒、クラウドには操作停止後約2秒で保存を予約します。

下書きはアカウントとブラウザの組み合わせ（`userId + deviceId`）ごとに分けます。同じアカウントを複数のブラウザで使っても、編集中の下書きを互いに上書きしません。保存できる有効な下書きは1アカウント10件まで、保持期間は30日です。

他のブラウザの下書きは、更新日時、ブラウザラベル、入力概要を確認してから、選んだものだけを復元できます。復元してもボックスの保存内容は変わりません。下書きの削除も明示操作で行います。計算結果、候補一覧、Workerの状態、チュートリアルは下書きへ含めません。

ページを閉じるときやバックグラウンドへ移るときに、未送信の変更を送信済みとは表示しません。未送信操作は`outbox`へ残し、次回の同期で再送します。リアルタイム共同編集や共有ボックスは提供していません。

### JSONバックアップ

各ボックス画面の`バックアップを書き出す` / `バックアップを読み込む`から、保存済みボックスをJSONファイルとして退避・復元できます。調整対象ボックスと仮想敵ボックスは別ファイルとして扱います。クラウド同期を利用している場合も、JSONバックアップは独立した復旧手段として利用できます。

バックアップファイルを選んだだけでは、作業中の入力条件や下書きは変わりません。バックアップ内の保存を選んで読み込んだ時点で、作業画面へ反映します。

## アカウント・同期管理

ヘッダーのアカウント画面と`Googleでログイン`は、未ログインでも利用できます。Googleログインで受け取るのは、表示名、メールアドレス、プロフィール画像、アカウント識別子です。Google Driveのファイル、連絡先、Gmailのメール本文を見る追加権限は要求しません。

同期状態は、次の7つの文言で表示します。

- `このブラウザのみ`
- `未同期`
- `同期中…`
- `同期済み`
- `オフライン`
- `競合あり`
- `同期エラー`

ブラウザへの保存とFirestoreへの保存は分けて判定します。未送信操作、競合、ネットワーク・権限・利用上限のエラーが残っている間は、`同期済み`と表示しません。必要なときは`今すぐ同期`で再確認できます。

アカウントデータを書き出すときは、手動同期後に、ボックス保存（Firestoreの`syncRecords`）とクラウド下書き（`drafts`）をサーバーから読み直します。読み取りエラー、未送信操作、競合、破損・未対応データが残る場合は、完全な書き出しとは表示せず、警告付きの部分書き出しまたは中止として扱います。

書き出すJSONには、形式の版（`schemaVersion`）、書き出し日時（`exportedAt`）、対象UID、サニタイズしたプロフィール、ボックス、クラウド下書きだけを含めます。認証情報、アクセストークン、Firebaseの公開設定、ゲスト領域は含めません。

アカウント削除では、必要に応じてGoogle popupで再認証します。続いて同じタブの同期と保存予約を停止し、対象UIDの`syncRecords`と`drafts`を最大450件ずつ削除します。両方が空になったことを確認してからUID専用のブラウザ内保存を削除し、最後にFirebase Authenticationのアカウントを削除します。

途中で失敗した場合は、Firebase Authenticationのアカウントを先に削除しません。失敗理由と再試行操作を表示します。最後のAuthentication削除だけが失敗した場合も、ログイン状態を維持して再試行できます。別ブラウザからの同時書き込みを完全には止められないため、削除後にクラウドを再確認してから処理を完了します。

アカウント削除で消すのは、そのUID専用の保存領域です。ログイン前からこのブラウザだけにあるゲストデータ、既存の`championcreator.box.v1` / `championcreator.enemy-box.v1`、既定サンプルの削除状態は残します。必要に応じて、ブラウザのサイトデータ削除や各ボックスの操作で別途削除してください。

FirebaseのWebアプリ用設定（Web config）は公開値として扱います。管理者用認証情報（Firebase Admin credential）、サービスアカウント鍵（service account key）、Google OAuth client secretは、ブラウザ配信用bundleやPages artifactへ含めません。GitHub Pagesの静的構成からFirebase client SDKを利用し、Admin SDKや独自のバックエンドは追加しません。

## 制限

- 本ツールは非公式のファンツールです。ゲーム内の結果と完全に一致することは保証しません
- 使用率順は Pokemon Champions Battle Data の `Current` データに基づくため、提供元の更新状況によって反映まで時間差が生じる場合があります
- Pokemon Champions と Showdown の仕様差、未対応データ、特殊処理により、実際のゲーム内結果と異なる可能性があります
- 一部のフォーム違い、技、特性、持ち物は未対応または仮対応の場合があります
- HPイベントは選択した効果が存在する前提で評価します。持ち物・状態・天候が入力と一致しない場合はUIで警告しますが、自動削除はしません。技失敗、`ちからずく`、持ち物の消費済み状態など、発動条件すべての自動推測は未対応です
- 現在は完了した通常技1回を1ターン境界として扱います。通常技の複数回指定では砂ダメージも各回に発生し、連続技では全ヒット後に1回だけ発生します。同一ターン内の複数行動をまとめる明示的なターン指定は未対応です
- 技固有の使用者側反動、HPコスト、使用者ひんしは通常の耐久・火力ラインへ自動適用しません。調整対象と仮想敵が交互に技を使い、どちらかのひんしで後続行動を止める完全な対戦進行は未対応です
- `ふんか`・`しおふき`・`ドラゴンエナジー`・`じたばた`・`きしかいせい`・`ハードプレス`など、対応済みの現在HP依存技は各攻撃時点のHPで再計算します。現在HPで発動条件が変わる全特性・全持ち物までを完全なバトル状態として再現するものではありません
- 条件ステッパーと任意威力は上記8技で使用できます。加えて現在HP依存技は、ロック解除中だけ自動計算を止めて入力威力を使用し、再ロックすると自動計算に戻ります。それ以外は入力済み条件から `@smogon/calc` が決めた威力を読み取り専用で表示します
- `ふくろだたき` は入力した参加ポケモンだけが攻撃するものとして評価します。ひんし・状態異常による参加可否は自動判定しないため、実際に参加できるポケモンだけを追加してください
- 調整対象のHPはシナリオ内で継続し、明示追加した`いのちのたま`・接触反動などの技使用者側HP変化も同じ攻撃カード内では継続します。別の攻撃カードを同じ技使用者として結び付ける指定は未対応です
- `しおづけ` は添付仕様に基づく Pokemon Champions 版（通常1/16、みず・はがね1/8）です
- `まきびし` の地面判定は現在UIで指定できる条件の範囲です。`じゅうりょく`、`うちおとす`、`ねをはる` など未入力の戦闘中状態までは扱いません
- 命中失敗そのものをシナリオ化していないため、`とびひざげり`などの失敗時反動は未対応です。`ニードルガード`、`ジャポのみ`、`レンブのみ`、`やどりぎのタネ`、`アクアリング`など、今回の対応一覧にないHP変化も未対応です
- キョダイマックスは将来ゲーム内実装される可能性がありますが、現時点では `@smogon/calc` の canonical species として存在しないため未対応です
- `@smogon/calc` に存在しないデータは、原則として計算の正として扱いません
- 素早さ調整の手動倍率は、選択中の持ち物・特性による自動補正を置き換える最終Sへの数値上書きです。特性の発動条件や丸め順まで完全に再現するものではなく、発動状態を直接指定する専用UIは未対応です
- 条件が複雑なほど探索に時間がかかります
- 重要な調整は実機でも確認してください
- ブラウザ別クラウド下書きは、Googleログイン後に初回統合を完了したアカウントで利用できます。1アカウント10件まで、保持期間は30日です。復元と削除は明示操作で行います。リアルタイム共同編集、共有ボックス、Google以外のログイン方法、チュートリアルの永続化は対象外です

### Firebase同期の技術境界

Firebase Web SDK、Google認証、Auth / Firestore Emulator、Firestore Security Rules、App Checkの初期化境界は`src/sync/`へ分離しています。Firebaseの必須Web configがない開発環境ではSDKを初期化せず、ブラウザ内保存だけで動作します。

調整対象・仮想敵ボックスは`/users/{uid}/syncRecords/{documentId}`、ブラウザ別クラウド下書きは`/users/{uid}/drafts/{deviceId}`へ保存します。保存内容のJSON文字列（`payload`）は既存parserで検証し、同期用の版番号、更新ID、server timestampと分離して扱います。

保存操作はブラウザへの確定を先に行い、未送信操作を順序付きキュー（`outbox`）へ残します。通常の削除は削除済み記録（`tombstone`）として同期し、競合解決と復元に必要な元データを保持します。破損したクラウド保存は1件ずつ隔離し、正常な一覧を維持します。

Google認証は標準プロフィールの取得だけに使い、追加のアクセス権は要求しません。Cloud FirestoreとAuthenticationにはApp Checkを適用しています。ローカルEmulator、Pagesの公開設定、Firebase Console、Rules、アカウントライフサイクルの運用手順は[`docs/FIREBASE_SETUP.md`](docs/FIREBASE_SETUP.md)を参照してください。
